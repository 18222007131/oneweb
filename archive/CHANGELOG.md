## 规则演进摘要

### v0.1 初始业务骨架

- 四角色 master/scheduler/reviewer/xiaoke。
- 入库预约、到货、台账、COP 请求基本链路。
- 账号库内外权限。

### v0.2 库房选择改为“用户不指定库房”

- 用户只填预约信息，不填库房。
- Scheduler 查询全部库房库存/状态，筛选候选。
- 用户从候选库房中选择。
- 库房编号规范：区域号+编号（A1/B2）。

### v0.3 预约表单去除果品温度

- 预约只填果品、吨位、时间、贮藏天数。
- Q1 使用果品推荐贮藏温区中间温度查 q_resp。
- 只有正式核算才询问果品中心温度。

### v0.4 COP 口径与热物性

- 单库房 COP 与机组分摊等效 COP 两种口径。
- q_resp 按果品+温度线性插值，W/t → W/kg。
- c 按冻结点选择高于/低于冰点档位。
- Q1/Q2 由系统计算，不允许外部直接提供。

### v0.5 reviewer 整改与演示模式

- reviewer 驳回后 scheduler 读取原因、向 master 确认整改指引、针对性修改重提。
- 记录修订版本，禁止原样重提。
- 正式模式 3 次兜底；演示模式 6 次兜底。
- reviewer 失败原因展示给用户。

### v0.6 库房前置硬筛选与入库超时

- Scheduler 预选校验品类/温区/湿度/库容/机组/占用。
- 无合格库房直接终止，不进入 reviewer。
- 入库超时禁止旧单继续入库。
- 超时询问是否重新预约；是则完整重跑，否则作废旧单。
- 设备异常同机组库房禁止新预约。

### v0.7 q_resp 条件温度对比基准修正

- 到货货温不再与“库房设定目标温度”比较。
- 改为与“生成 q_resp 时使用的条件温度”比较。
- 预约 COP 预估把 q_resp 条件温度写回预约单。
- 该版本仍是“温度参与触发”的中间版本。

### v0.8 到货偏差改为仅吨位触发

- **温度不再作为是否重规划的判断条件。**
- 只按 `|实际吨位-预约吨位|/预约吨位 > 5%` 触发增加/更换库房。
- q_resp 条件温度仍查询、记录、展示。
- q_resp 条件温度 + PLC 参数写入 `thermalPlcHistory`。
- 日志保留 q_resp 条件温度、到货货温、吨位、吨位偏差。
- 旧“温度偏差%”字段不再生成。

### v0.9 库房前置核验时序修正

- 原来用户先选库房、reviewer 后续才发现温湿度不匹配；修正为：
  - scheduler 硬预选；
  - reviewer 前置快速核验；
  - 通过后才展示给用户；
  - 不通过回退 scheduler 重选，不进入用户选择，不进入普通整改。
- 日志逐间打印比对、淘汰原因、最终候选核验结果。
- 无合格库房直接终止。

### v1.0.0 内置温湿度参数传递修复（冻结）

- 确认 FRUIT_SPECS 完整（杨梅/柚子/苹果）。
- 预约单/到货单/重规划新单携带完整温湿度要求字段。
- reviewer payload 携带 `builtInFruitSpecs` 和 `documentFruitSpec`。
- reviewer 本地规则兼容 `tempZone`/`temperatureRequirement`/`fruitSpec`。
- 修复“预约单缺少内置温湿度参数”误判。
- 冻结为平台开发需求与回归基准。

## 已废止规则（禁止在平台回归中使用旧期望）

| 旧规则 | 废止版本 | 现行规则 |
|---|---|---|
| 到货货温 vs 库房目标温度计算偏差并触发重规划 | v0.7 起不再用库房目标；v0.8 起不触发 | 温度只记录，不触发；只按吨位 |
| 到货货温 vs q_resp 条件温度计算偏差并触发重规划 | v0.8 | 温度只记录、写历史；只按吨位 |
| 温度偏差 >5% 可单独触发增加/更换库房 | v0.8 | 只有吨位偏差 >5% 触发 |
| 预约表单收集果品温度 | v0.3 | 不收集；Q1 用推荐温区中间温度 |
| 用户先选库房，随后 reviewer 再报温湿度不匹配 | v0.9 | 前置 reviewer 核验在用户选择之前 |
| 无合格库房仍让用户选择或进入 reviewer | v0.9 | 直接终止，不进入 reviewer |
| 前置核验失败进入普通单据整改重试 | v0.9 | 回退 scheduler 重选库房 |
| reviewer payload 不带内置果品温湿度参数 | v1.0.0 | 必须带 `builtInFruitSpecs`/`documentFruitSpec` |
| 到货偏差重规划消耗普通整改次数 | v0.8 | 不消耗 |
| 无入库单/无预约单仍继续 COP 核算 | v0.4 | 生成核算异常警报并终止 |

## 归档不变量

1. 冻结版本目录不可原地修改；新规则新增版本目录。
2. 任何规则变更必须同时更新：
   - `01_requirements_baseline.md`；
   - `02_rules_and_boundaries.md`；
   - `03_regression_cases.json`；
   - `04_test_evidence.md` 或新证据；
   - 本 CHANGELOG。
3. 平台回归必须使用当前冻结版本的期望，不得使用历史版本中被废止的行为。
